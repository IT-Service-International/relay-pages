02 / THREE WAYS TO BUILD

Adapt

Fit an existing client tool or script to a defined environment.

Deliverables: scoped modifications, configuration notes and agreed checks.

Build

Create a focused tool, report or automation for a repeatable task.

Deliverables: source code, configuration guidance, test evidence and an operator guide.

Integrate

Connect systems into a workflow with clear ownership and failure handling.

Deliverables: interface design, integration code, deployment and rollback instructions, and handover.

Custom quotation after discovery. Source delivery, usage rights, third-party dependencies, support and maintenance are agreed in the proposal.

03 / FROM REQUEST TO HANDOVER

  1. Describe the outcome

    Share the problem, environment, constraints and target date. Start with a short, non-confidential brief.

  2. Discover & scope

    Review dependencies, platform support and access needs. Agree deliverables, exclusions, acceptance tests, price and milestones before implementation.

  3. Prototype & review

    Validate the approach using sample or test data. Review the output together before expanding the implementation.

  4. Build & verify

    Implement the agreed scope, document configuration, test expected and failure paths, and record results.

  5. Deploy & hand over

    Use an approved change window and rollback plan. Deliver agreed source, documentation and knowledge transfer; confirm acceptance against the defined criteria.

  6. Maintain by agreement

    Choose whether to arrange ongoing support. Changes to scope, support coverage or platform compatibility are agreed separately.
